# 常见问题与排错指南

## 上传问题

### 上传后文档状态不变

可能的原因：
1. ETL 流水线尚未执行完毕，请等待 1-2 分钟
2. 如果长时间处于 UPLOADED 或 PROCESSING 状态，请检查后端日志
3. 可能是 MinIO 服务未启动或网络不通

### 上传失败

可能的原因：
1. 文件格式不支持（仅支持 .txt、.md、.pdf、.docx）
2. 文件大小超过 256MB 限制
3. 网络连接不稳定，可以尝试使用分片上传（支持断点续传）
4. 群组权限不足，需要群组 OWNER 才有上传权限

### 文件预览为空

可能的原因：
1. 文档尚在 PROCESSING 状态，预览功能仅在 READY 状态可用
2. PDF 或 DOCX 解析器未能提取到文本内容
3. 文件本身为扫描件（图片型 PDF），需要 OCR 支持

## 检索问题

### 提问后没有回答

可能的原因：
1. 知识库群组中没有已处理完成的文档
2. 问题与知识库内容无关，系统判定证据不足后自动拒答
3. 证据等级低于 SUFFICIENT，模型无法给出有依据的回答

### 回答质量不佳

可能的原因：
1. 切片策略导致关键信息被分割到不同的 chunk 中
2. 检索到的文档与问题相关性不足
3. 问题太模糊，需要更具体

### 引用不准确

可能的原因：
1. 混合检索命中了不相关的文档
2. RRF 融合排序分数差异不明显
3. 邻居窗口扩展引入了无关内容

## 性能问题

### 响应慢

可能的原因：
1. 查询规划阶段的 LLM 调用耗时
2. 混合检索需要依次执行向量和关键词两路检索
3. 大模型生成回答需要时间

优化建议：
1. 如果查询规划耗时过长，可以在配置中将 query-planning-enabled 设为 false
2. 使用 pgvector 的 HNSW 索引替代 IVFFlat 索引
3. 适当减小 CHANNEL_TOP_K 的值

### 数据库查询慢

可以尝试的优化：
1. 检查 PostgreSQL 的查询计划，确认是否使用了索引
2. 为 pg_trgm 创建 GIN 索引
3. 定期执行 VACUUM ANALYZE

## 系统管理

### 如何查看文档处理进度

可以通过文档 API 查询文档状态，READY 表示处理完成，FAILED 表示处理失败。

### 如何重新处理失败的文档

对于状态为 FAILED 的文档，可以通过文档管理界面的"重新处理"按钮或调用 retry-ingestion 接口重新触发 ETL 流程。

### 日志如何查看

后端日志默认输出到控制台和 logs 目录下的日志文件。关键操作均有日志记录，包括：
- 上传操作日志
- ETL 流水线各步骤日志
- LLM 调用日志
- 认证鉴权日志
