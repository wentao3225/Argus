## 一、上传路径测试

### 1.1 小文件直接上传 ✅（已验证）

覆盖文件：`01-文件上传流程说明.md`

前序测试中已使用 `Argus-会话背景.md` 完成验证，步骤不再重复。

---

### 1.2 分片上传（正常链路）

> 需准备一个 >10MB 的文件，用户自行准备。

**操作步骤**：使用前端上传对话框，选择 >10MB 的文件 → 自动进入分片上传模式 → 逐片上传 → 完成合并。

**验证点**：
- [ ] 选中文件后前端显示"分片上传 · N 片"标签
- [ ] 进度条显示"分片 x/N · y%"
- [ ] 完成后文档出现在列表
- [ ] ingestion 日志完整：reader → parser → clean → chunk → embed → index

---

### 1.3 断点续传

> 需准备一个 >10MB 的文件，用户自行准备。

**操作**：
1. 在前端选择大文件开始上传
2. 上传过程中强行关闭浏览器或刷新页面
3. 重新打开上传对话框，选择相同文件
4. 观察是否从断点处继续上传

**验证点**：
- [ ] 重新 init 后返回相同 uploadId
- [ ] 已上传的分片不重复上传
- [ ] 补完缺失分片后完成成功

---

### 1.4 秒传检测

**操作**：将已上传过的文件再次拖入上传对话框 → 点击开始上传

**验证点**：
- [ ] 秒传触发（进度条直接跳到 100%）
- [ ] 不创建重复文档

---

### 2.2 TXT 文档

**准备**：将任一 `.md` 测试文件复制为 `.txt` 格式上传

```
cp docs/test/samples/01-文件上传流程说明.md docs/test/samples/01-文件上传流程说明.txt
```

**操作**：通过前端直接上传 `.txt` 文件

**验证点**：
- [ ] 文档状态变为 READY
- [ ] 预览内容与原始文件一致
- [ ] 检索可命中内容

---

### 2.3 PDF 文档

**准备**：将任一 `.md` 测试文件转换为 PDF（可用浏览器打印另存为 PDF，或用 pandoc）

```
# 可选：使用 pandoc 转换（需安装 pandoc + wkhtmltopdf）
pandoc docs/test/samples/01-文件上传流程说明.md -o docs/test/samples/01-文件上传流程说明.pdf
```

**操作**：通过前端上传 `.pdf` 文件

**验证点**：
- [ ] 文档状态变为 READY（而非 FAILED）
- [ ] 预览返回纯文本内容
- [ ] 检索结果命中 PDF 中内容

---

### 2.4 DOCX 文档

**操作**：通过前端上传 `.docx` 文件

## 三、检索场景测试

> 准备工作：将 01~05 所有样本文件上传到同一个群组（建议新建一个空群组），等待全部变为 READY。

### 3.1 直接命中（关键词匹配）

**使用文件**：`01-文件上传流程说明.md`

**提问**：
```
分片上传的流程是什么？
```

**预期**：
- [ ] 检索到 chunk 6（分片上传章节）
- [ ] evidenceLevel = SUFFICIENT
- [ ] 回答包含分片上传三步流程

---

### 3.2 语义匹配（无关键词重叠）

**使用文件**：`02-Argus知识库平台技术架构.md`

**提问**：
```
系统用了什么方法来让回答不会凭空编造信息？
```

> 文档中没有直接出现"幻觉编造"等词，但有"四级证据评估、证据不足时主动拒答"的语义

**预期**：
- [ ] 向量检索命中（语义相似，关键词无重叠）
- [ ] 关键词检索可能无结果或结果较少
- [ ] 回答提到证据评估机制

---

### 3.3 跨文档综合

**使用文件**：`02-技术架构.md` + `03-数据模型设计.md` + `04-pgvector指南.md`

**提问**：
```
pgvector 在系统中扮演什么角色？数据是如何从文档变成向量并存储的？
```

> 需要综合多个文档的信息：pgvector 的作用（04）、切片流程（02）、向量存储结构（03）

**预期**：
- [ ] 引用包含多个文档
- [ ] evidenceLevel = SUFFICIENT
- [ ] 回答完整覆盖"文档→切片→向量化→HNSW 索引→检索"链路

---

### 3.4 同类问题不同文档

**使用文件**：`01-上传流程.md` + `05-常见问题.md`

**提问**：
```
上传后文档状态一直不变怎么办？
```

> 01 文档中有"常见问题"小节，05 文档中有专门排错指南

**预期**：
- [ ] 检索命中两个文档的相关章节
- [ ] 回答综合了多个来源的信息

---

### 3.5 证据不足（拒答）

**使用文件**：任意已上传的样本（或无文档的空群组）

**提问**：
```
贵公司今年的财务报告怎么样？
```

> 知识库中没有任何财务相关内容

**预期**：
- [ ] evidenceLevel < SUFFICIENT（应为 NONE 或 WEAK）
- [ ] 返回 answered=false
- [ ] 前端展示拒答提示

---

### 3.6 查询规划（REWRITE）

**使用文件**：`01-文件上传流程说明.md`

**提问**：
```
我想往知识库里放点东西，具体该怎么做？
```

> 口语化表达，触发 REWRITE 策略

**预期**：
- [ ] 日志显示 strategy=REWRITE，生成改写查询
- [ ] 检索命中上传流程相关章节
- [ ] 回答正确

---

### 3.7 查询规划（DECOMPOSE）

**使用文件**：混合（01 + 02 + 05）

**提问**：
```
文件上传失败怎么办？上传完成后系统做了什么处理？
```

> 包含两个独立子问题，触发 DECOMPOSE

**预期**：
- [ ] 日志显示 strategy=DECOMPOSE，生成两个子查询
- [ ] 检索到上传失败处理 + ETL 流水线相关内容
- [ ] 回答覆盖了两个问题
