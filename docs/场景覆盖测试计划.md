> 文档版本：2026-06-03
> 测试目标：验证所有上传路径、文档格式、检索场景的端到端正确性

## 一、上传路径测试

### 1.1 小文件直接上传 ✅（已验证）

已有测试记录。不再重复。

---

### 1.2 分片上传（正常链路）

**准备**：找一个 >10MB 的文件（或调小分片大小模拟多个分片）

**操作**：

```
# Step 1: 初始化上传会话
POST /api/documents/upload/init
{
  "groupId": <groupId>,
  "fileName": "test.pdf",
  "fileSize": 15728640,          # 15MB
  "chunkSize": 5242880,          # 5MB/片 → 3片
  "fileHash": "<sha256>"
}
# → 返回 uploadId, chunkSize, chunkCount

# Step 2: 逐片上传
POST /api/documents/upload/chunks
Content-Type: multipart/form-data
{
  "uploadId": "<uploadId>",
  "chunkIndex": 0,               # 第一片
  "chunk": <binary>
}
# → 重复 3 次

# Step 3: 完成合并
POST /api/documents/upload/{uploadId}/complete
# → 触发 ETL，文档状态变为 PROCESSING → READY/FAILED
```

**验证点**：
- [ ] 每个 chunk 上传后返回 200
- [ ] complete 后文档出现在列表
- [ ] ingestion 日志：reader → parser → clean → chunk → embed → index
- [ ] 可正常搜索该文档内容

---

### 1.3 断点续传

**准备**：接 1.2，上传 2 片后中断（不调 complete）

**操作**：

```bash
# 再次用相同 fileHash 调 init
POST /api/documents/upload/init
{ ... 相同参数, 相同 fileHash ... }
# → 返回相同 uploadId，resumed=true

# 查看已上传分片（前端应有提示哪些片已上传）
# 上传剩余分片
# 调 complete
```

**验证点**：
- [ ] init 返回 `resumed=True` 或相同 uploadId
- [ ] 已上传的分片不重复上传
- [ ] 补完缺失分片后 complete 成功

---

### 1.4 秒传检测

**准备**：接 1.2，完成过一份文档

```bash
# 上传完全相同文件
POST /api/documents/upload/init
{ ... 相同 fileHash ... }
# → 返回 completeUrl 或 409 状态码，提示文档已存在
```

**验证点**：
- [ ] 秒传触发，不走完整上传流程
- [ ] 原有文档状态不变

## 二、文档格式测试

### 2.1 PDF 文档

**准备**：准备一份含标题、段落、列表的 PDF

**上传方式**：直接上传（小文件）

**验证点**：
- [ ] 文档状态变为 READY（而非 FAILED）
- [ ] 预览返回纯文本内容
- [ ] 检索结果命中 PDF 中内容

### 2.2 DOCX 文档

**准备**：一份带章节标题的 Word 文档

**验证点**：
- [ ] parser 正确提取文本
- [ ] 切片保留段落结构
- [ ] 可检索到内容

### 2.3 MD / TXT 文档

**准备**：不同编码（UTF-8 / GBK）的纯文本文件

**验证点**：
- [ ] 编码检测正确，无乱码
- [ ] 切片正确

### 2.4 不支持格式

**准备**：上传 `.png` / `.zip` 等不支持的文件

**验证点**：
- [ ] 上传接口返回 400（格式不支持）
- [ ] 或文档状态变为 FAILED 并给出错误原因

## 三、检索场景测试

所有问题基于群组 2（已有文档 + 新上传的测试文档混合）。

### 3.1 直接命中

```
Q: <问题中包含文档中的确切关键词>
```

- [ ] 检索结果包含该 chunk
- [ ] evidenceLevel = SUFFICIENT
- [ ] 回答有引用

### 3.2 语义匹配（无关键词重叠）

```
Q: <表达相同含义但用词完全不同>
```

- [ ] 向量检索命中（语义相似）
- [ ] 关键词检索可能无结果
- [ ] 回答正确

### 3.3 跨文档综合

```
Q: <需要从多个文档中综合信息>
```

- [ ] 引用包含多个文档
- [ ] evidenceLevel = SUFFICIENT
- [ ] 回答内容综合了多份来源

### 3.4 证据不足（拒答）

```
Q: <问知识库中完全没有的内容，如"当前公司的年度财报如何">
```

- [ ] evidenceLevel < SUFFICIENT
- [ ] 返回 answered=false，reasonCode=INSUFFICIENT_EVIDENCE
- [ ] 前端展示拒答提示

### 3.5 查询规划（REWRITE/DECOMPOSE）

```
Q: <模糊问题，如"文档上传流程是什么，切片后如何入库">
```

- [ ] 日志显示 strategy=REWRITE 或 DECOMPOSE
- [ ] 检索到相关内容
- [ ] 回答正确

## 四、边界条件测试

### 4.1 空群组

- [ ] 对没有任何已处理文档的群组提问 → 拒答

### 4.2 仅有异常文档的群组

- [ ] 上传一个格式错误的文件（如空的 TXT） → 状态 FAILED
- [ ] 对该群组提问 → 拒答

### 4.3 短文档（1 个 chunk）

- [ ] 上传一句话的 TXT → 只有 1 个 chunk
- [ ] 检索时应正常命中

### 4.4 长文档（多 chunk）

- [ ] 上传长文档（如面试笔记、技术手册） → 很多 chunk
- [ ] 邻居窗口扩展应提供上下文
